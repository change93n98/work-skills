# Codex 远程节点配置

一个入口管理两个独立模块：模型请求的网络代理，以及远程文件的编辑器跳转。先判断用户要解决哪一个问题，再读取相应文档；不要把两个模块的成功当成彼此的验证。

## 选择模块

| 用户诉求 | 读取与执行 | 修改边界 |
| --- | --- | --- |
| SSH 本地代理、模型重连、认证网页连接失败 | [SSH 代理](references/ssh-proxy.md) | 仅目标节点的网络设置；已有自动重连隧道优先复用 |
| 点击远程文件打不开、Kylin 跳转、指定行号定位 | [编辑器文件打开](references/editor-open.md) | 仅自定义编辑器、桥接脚本和目标节点路由 |
| 给指定节点完整配置远程 Codex | 先检查上述两个模块，按实际缺项分别配置 | 不适用模块说明原因；不默认给普通节点安装 Kylin |
| 只检查或询问是否可用 | 只读检查相关模块 | 不部署、不改配置、不打开测试文件、不调用模型 |

## 共同入口与前提

- 在运行 Codex 桌面端和本地代理的电脑执行。目标是用户 SSH config 中的别名，保留 User/Port/IdentityFile/ProxyJump；从实际配置和节点环境发现信息，不在 skill 中维护节点清单。
- 指定节点只处理该节点；用户明确要求全部时才扩展范围。完全没给节点时列出别名询问，不猜目标。
- 代理脚本的 `--list` 可用于列出当前 SSH config 的显式别名：`python scripts/proxy/set_codex_ssh_proxy.py --list`。其 Include/通配符限制见代理模块；需要完整有效配置时用 `ssh -G`。
- 修改前备份所涉配置和脚本，保留无关设置。已有会话、自动重连守护、编辑器路由应先识别后复用。
- 不复制 ChatGPT 登录令牌、API key、代理订阅、SSH 私钥或 Remote - Dev 证书到 skill 仓库。不关闭 TLS 校验、不改模型供应商、不替换系统 VS Code 协议处理程序。
- 配置文件跳转不调整网络或模型；配置代理不修改编辑器。文件桥接使用普通 SSH 命令，与模型 API 的 HTTP 代理链路分别检查。
- 不自动重启正在运行当前对话的桌面端，不杀其他会话或其他用户的进程。

## 执行与交付

代理模块从根目录执行 `scripts/proxy/set_codex_ssh_proxy.py`；Kylin 模块从根目录执行 `scripts/kylin/render_bridge.py`。脚本参数、前提和验证标准只在对应模块维护。

报告每个请求模块的结果及证据：

- 网络：代理/直连对照、实际进程环境和传输错误。HTTP 401 只证明到达认证关卡，不证明已建立 WebSocket 或完成推理。
- 编辑器：正确主机、文件、行列号，以及真实 Codex 菜单点击结果。IPC 返回成功不能替代编辑器画面核验。
- 已修改哪些文件、备份位置、是否需要用户重新连接或重启，以及尚未验证的事项。

只验证所请求的范围。合并或安装 skill 本身不意味着重新配置了所有节点，也不意味着补齐了之前未完成的真实 UI 测试。

## 维护验证

```text
python -m unittest discover -s tests/proxy -p "test_*.py" -v
python scripts/kylin/test_render_bridge.py
```

同时检查引用路径、TOML/YAML、生成实例和源码中的敏感信息。内部受管标记、旧部署路径和日志名称可以保留用于兼容，不能为了重命名 skill 而无故迁移正在工作的运行环境。
