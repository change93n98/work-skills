# 固定分类表模板 v2.1（dense 兼容）

用户已认可当前分类表样式，后续新建报告必须复用，不在每次调用时重新设计。只有用户明确要求调整布局/样式时才修改模板，并同时更新版本和回归校验。

## 唯一实现与版本

- `assets/report-layout.json` 使用 `llm-prof-classification-v2.1`。沿用已认可的字体、字号、颜色、表格样式、数字格式及子表顺序。GDN 子项按实际设备核展示，跨卡对比组另见 [GDN 分类和跨卡对齐](gdn-classification.md)。
- `scripts/report_template.mjs`：当前已认可分类表的实际渲染器，包含公式、时间核算、条纹表格、冻结行、未知/歧义提示。
- `scripts/export_prof_report.mjs`：导出入口，window/step 使用上述渲染器。批量可传入 `{"mode":"batch","title":"目录名","reports":[各rank选定窗口JSON...]}`；每个 rank 仅一份选定窗口，禁止混入其他 step 或 prefill。
- Python JSON 记录模板版本与 SHA256，XLSX“选窗依据”底部也记录模板版本和校验值，便于核对样式来源。

不要绕过默认渲染器临时拼表或依赖表格库的默认主题。调用数据、标题、规则版本、平台和时间随本次输入变化；样式固定不意味着固定历史数值或硬编码某个厂商。

## 固定新报告结构

1. **分类汇总**：标题第2行、说明第3/4行、表头第5行。基础六类每 rank 为13行，有 group gemm 或 GDN 时各加一个主类行。原生 trace 把 GDN 算子明细插入 GDN 主行下方，导出为默认折叠的 Excel 行分组。汇总按子表2的选区计算，默认 decode step2。
2. **Kernel明细**：表头第1行，前六列保持原 Perfetto SQL；其后为类别、分类规则、语义子类、置信度、歧义、rank、窗口、窗口ID、来源 trace。
3. **选窗依据**：两端 annotation、首设备事件、category、开始偏移、device/stream、correlation、关联方式、置信度和歧义计数；下方列出本窗口覆盖与时间数据。手工窗口明确标为用户给定边界，不伪造 correlation。

分类汇总列顺序固定：rank、窗口、类别/时间项、调用次数、kernel种类、总耗时(µs)、总耗时(ms)、主类内占比、窗口占比、窗口(ms)、未知种类。

native 同名核有逐次来源分项时，“Kernel明细”原表保留，下方追加相同列格式和条纹样式的“分类分项”表，分类汇总公式只引用分项表。分项调用数、dur 和原名字行守恒；类别内的 kernel种类按分项名字计数，同一个名字可出现在两个类别。“选窗依据”追加类别已确定但 launch 冲突的候选 ID、scope 和两种置信度。未发生拆分或冲突时不增加对应内容。

分类顺序沿用基础六类，MoE 专家 group gemm 放在 gemm 后，GDN 放在 FlashAttention 后。类别行后依次是主类合计、等待/同步 WAIT/SET、设备调用合计（加总）、重叠/边界调整、设备覆盖时长（去重）、空泡和窗口总时间。行号和 rank 块偏移按实际类别数计算，GDN 算子行只作分解展示。

默认一份报告只含选定窗口；支持任意 step 不意味着默认导出全部 step。多 rank 分开汇总，不跨卡相加。分类文件放在各自 trace 目录，根目录总览仅汇集这些已选结果。现有文件被占用时说明原因并另存清晰版本，不能结束占用进程或静默覆盖其他结果。

最终文件按 [交付目录整理](window-and-xlsx.md#交付目录整理) 收尾：每组顶层保留原始 trace 和 decode、prefill 两份最新分类表；JSON/CSV/SQL/TXT、核验资料、日志配置及旧表放入“分析辅助资料”。只要求一个阶段时不增加另一阶段，跨组对比表放共同上级目录；整理文件位置不改变表格样式、分类、选窗或统计口径。

## 固定视觉样式

- Arial 正文/表头10pt、标题14pt；深蓝 `#253B58` 表头、白字、居中换行，表头高36。
- 正文高23，隐藏网格线；汇总与明细使用显式 `TableStyleMedium2` 蓝色条纹及筛选。
- 汇总冻结前5行，明细/选窗依据冻结表头。列宽严格采用 JSON 中的数组。
- 次数整数 `#,##0`，耗时 `#,##0.000`，比例 `0.00%`；SQL 明细的原百分数仍显示 `0.00`，不错误缩放100倍。
- 未知项及后续关联歧义用浅黄 `#FFF2CC` 和深色提示；空泡、窗口总时间加粗，总时间上方细边框。不得用装饰性状态替代真实置信度/歧义。
- 重新分类已有 XLSX 时保留原有子表、旧列、原始数据格式和顺序。新增汇总使用同版配色、字体、精度和 GDN 折叠方式。缺少逐事件区间时，空泡显示 `n.a.`。

## 空泡和总时间：必须展示的口径

总时间是当前片选窗口的 `end-start`。设备调用加总来自子表2的 dur，包括 WAIT/SET；覆盖时间则从**同一窗口**的逐次设备事件合并重叠、裁剪边缘，并补入窗口前开始但仍在执行的部分，不汇总其他片段。

```text
窗口总时间 = 设备覆盖时长 + 空泡
设备调用加总 + 重叠/边界调整 = 设备覆盖时长
空泡 = 窗口总时间 − 设备覆盖时长
```

WAIT/SET 作为边界候选和设备轨迹覆盖保留，并单列等待/同步；分类占比以当次主类别调用耗时为分母。当前空泡是所选设备轨迹未覆盖的时间，不能把 WAIT 内部时间再次算为空泡，也不能把多流 dur 之和当墙钟覆盖或GPU利用率。

例如已验证的 LX step2：窗口75.822080ms；调用加总57.497450ms；重叠调整−0.011675ms；覆盖57.485775ms；空泡18.336305ms。示例只说明恒等式，不作为后续报告的默认数据。

仅有按 name 聚合的 XLSX 缺少逐事件 ts/dur，无法计算精确去重空泡；新增汇总保留空泡/覆盖/总时间项并标 `n.a.`、说明缺少什么证据，不从已四舍五入百分比冒充精确窗口。

## 验证

运行 `test_report_time_accounting.py` 实际导出再回读，核对表序、字体、表头色、列宽、冻结、条纹样式、数字格式以及 WAIT/覆盖/空泡/总时间恒等式。样式回归失败时修复渲染器，不改成另一个临时排版。

批量汇总公式只引用各 rank/窗口对应的明细块，避免反复扫描全表造成内存膨胀。导出后检查明细守恒和来源引用，渲染关键范围比对已认可模板；没有新增数据或样式变更时不重复重跑原始 profiling。
